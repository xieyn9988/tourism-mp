# 门票使用生命周期设计

日期：2026-11-11
状态：已与需求方确认，待实现

## 1. 目标与背景

当前系统允许订单在任意已支付阶段分账，只要求至少有一个已核销子项。这会让游客还在园内、未核销项目仍可能退款时，订单就被提前分账，造成后续退款与商户结算冲突。

本次引入“门票使用生命周期”：

- 生命周期从门票核销（入园）开始；
- 游客离园（出口扫码）或景区闭园后，本次游园进入结束流程；
- 只有生命周期结束后，订单才允许分账；
- 离园后未核销项目是否还能退款，由园区运营方配置；
- 若允许离园后退款，退款窗口从 `leave_at` 起算，默认 72 小时（三天）；
- 再次进入景区必须重新购票，已结束生命周期的订单不能继续核销。

## 2. 术语

- **入园时间 `entered_at`**：订单内第一条“门票”子项核销成功的时间（UTC）。
- **离园时间 `exited_at`**：出口扫码登记的时间（UTC）。允许为空。
- **离开时间 `leave_at`**：本次游园实际结束的基准时间，取离园扫码时间与当日闭园时间中较早者：
  `leave_at = min(exited_at, closing_at(entered_at))`。
- **闭园时间**：固定时区 UTC+8 下当天的 `PARK_CLOSE_TIME`，默认 `18:00`。
- **终态子项**：`verified`（已核销）或 `refunded`（已退款）。
- **待处理子项**：`unverified`（未核销）。

## 3. 生命周期状态

派生状态，不落库；每次读取时按订单字段、子项状态、园区配置和当前时间实时计算。

| 状态 | 含义 |
| --- | --- |
| `not_applicable` | 订单不含门票，生命周期规则不适用 |
| `not_started` | 含门票，但门票尚未核销，生命周期未开始 |
| `active` | 已入园，生命周期进行中 |
| `completed` | 生命周期已结束，允许分账 |

结束原因 `reason`：

| reason | 触发条件 |
| --- | --- |
| `not_applicable` | 订单不含门票 |
| `not_entered` | 含门票但未入园，且当前未闭园 |
| `park_closed` | 含门票但未入园，且当前已过当日闭园时间 |
| `in_park` | 已入园，尚未离园/闭园，存在待处理子项 |
| `post_leave_refund_window` | 已离园/闭园，园区允许离园后退款，退款窗口尚未到期 |
| `all_items_settled` | 全部子项均为终态（已核销或已退款） |
| `refund_window_expired` | 已离园/闭园，园区允许离园后退款，但退款窗口已到期 |
| `post_leave_refund_disabled` | 已离园/闭园，园区不允许离园后退款 |

## 4. 结束判定（已确认）

满足以下任一条件，生命周期立即结束：

1. **全部子项已终态**：所有子项都是 `verified` 或 `refunded`。此时无论是否离园、退款配置如何，均立即结束。
2. **存在待处理子项，且园区允许离园后退款**：当前时间 `>= leave_at + refund_window_hours` 时结束。
   - 退款窗口从 `leave_at` 起算；
   - `refund_window_hours` 由运营方配置，默认 `72`；
   - 窗口内 `active`，可退款、不可分账。
3. **存在待处理子项，且园区不允许离园后退款**：当前时间 `>= leave_at` 时结束。

补充规则：

- 未入园（`entered_at IS NULL`）时生命周期未开始，不允许分账；
- 已入园但未到闭园、未扫码离园时，生命周期进行中，不允许分账；
- 已入园且全部子项终态时，即使没有 `exited_at`，也立即结束；
- `entered_at` 为空的历史订单按“未入园”处理；迁移时对已有已核销门票的记录用最早核销时间回填 `entered_at`，避免旧数据被永久卡住；
- `leave_at` 的计算不落库，避免闭园时间变化后历史数据失真。

## 5. 运营配置

新增 `park_settings` 单行配置表（`id = 1`）：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `refund_after_lifecycle` | bool | `false` | 离园/闭园后是否仍允许未核销子项退款 |
| `refund_window_hours` | int | `72` | 离园后退款窗口小时数，取值 0–8760 |

- 默认不允许离园后退款，即离园/闭园时未核销项目立即失去退款资格，生命周期立即结束。
- 配置修改只影响后续计算，不回溯已生成的分账流水。
- 读取接口不需要签名；修改接口需要 HMAC 签名。

## 6. 业务动作约束

### 6.1 核销

- 门票核销成功时，若 `entered_at` 为空，写入当前 UTC 时间。
- 未入园且已过当日闭园时间：拒绝核销门票，提示“景区已闭园，今日无法检票入园”。
- 非门票项目仍要求先核销门票（保持现有规则）。
- 生命周期为 `completed`，或已离园/闭园且 `can_verify = false`：拒绝核销，提示“本次游园已结束，如需再次入园请重新购票”。
- 已核销、已退款子项的拒绝提示保持现状。

### 6.2 离园登记

新增 `POST /api/verify-records/{record_id}/exit`：

- `record_id` 可以是订单内任意一条核销记录（通常二维码里的门票记录）；
- 不需要 HMAC 签名（出口闸机场景）；
- 幂等：首次写入 `exited_at`，后续重复调用返回 200，不覆盖首次离园时间；
- 未入园（`entered_at IS NULL`）返回 409；
- 返回该订单最新的生命周期快照。

### 6.3 退款

- 保留现有规则：已分账不可退；已退款不可重复退；已核销子项不可退；只退未核销子项。
- 新增生命周期门槛：
  - `can_refund = true`：未入园、园内、离园后退款窗口内；
  - `can_refund = false`：生命周期已结束。
- 生命周期已结束时返回 409，detail 使用生命周期消息，明确“游园已结束，不可退款”。

### 6.4 分账

- 保留现有规则：未支付不可分账、已分账不可重复分账、至少一个已核销子项。
- 新增门槛：仅生命周期 `completed` 或 `not_applicable` 时允许分账。
- 生命周期未结束时返回 409，detail 使用生命周期消息，说明还需等待离园/闭园或退款窗口结束。
- 分账仍只结算 `verified` 子项；未核销/已退款子项金额、抽成、实得均为 0。

### 6.5 再次入园

- 已结束生命周期的订单不能继续核销任何子项；
- 游客再次进入景区必须购买新订单；
- 系统不提供“重新激活”接口。

## 7. 接口

### 7.1 `GET /api/order/{order_id}/lifecycle`（无需签名）

返回：

```json
{
  "order_id": 1,
  "status": "active",
  "reason": "in_park",
  "entered_at": "2026-11-11T02:00:00",
  "exited_at": null,
  "leave_at": "2026-11-11T10:00:00",
  "refund_deadline": null,
  "refund_after_lifecycle": false,
  "refund_window_hours": 72,
  "can_verify": true,
  "can_refund": true,
  "can_split": false,
  "message": "游客在园内，生命周期进行中；离园或闭园后按规则结束。"
}
```

时间字段为 UTC naïve ISO 字符串，前端展示时转换为 UTC+8。

### 7.2 `POST /api/verify-records/{record_id}/exit`（无需签名）

返回同一结构；重复调用返回 200。

### 7.3 `GET /api/park-settings`（无需签名）

```json
{"refund_after_lifecycle": false, "refund_window_hours": 72}
```

### 7.4 `PUT /api/park-settings`（需要 HMAC 签名）

请求体：

```json
{"refund_after_lifecycle": true, "refund_window_hours": 72}
```

`refund_window_hours` 取值 0–8760，超出返回 422。

## 8. 前端（app_scan.py）

### 8.1 商家核销

- 岗位下拉新增“景区出口”；选中后扫码调用离园接口，而不是核销接口。
- 成功时显示“离园登记成功”，并提示生命周期是否已结束、是否可分账。
- 未入园时提示“尚未入园，无法离园”。

### 8.2 游客订单状态

- 在现有订单状态卡片下方增加生命周期区域：
  - 状态徽章：未入园 / 游园中 / 已结束 / 不适用；
  - 入园、离园（或预计闭园）、退款截止时间；
  - “可分账 / 分账待生命周期结束”“可退款 / 不可退款”提示；
  - 后端 `message` 原样展示。
- 生命周期接口不可用时静默降级，不影响本地订单状态展示。

### 8.3 运营后台

- 新增“园区退款规则”区域：
  - 复选框“离园后仍允许退款”；
  - 数字输入“离园后退款窗口（小时）”，默认 72；
  - 保存按钮调用签名 `PUT /api/park-settings`；
  - 页面加载时读取并回填当前配置。
- 说明文案明确：分账只在生命周期结束后执行。

## 9. 非目标

- 不做多日票、多次入园、年卡；
- 不做闸机硬件对接、二维码离线校验；
- 不做闭园时间的图形化配置（闭园时间仍由 `PARK_CLOSE_TIME` 环境变量控制，默认 `18:00`）；
- 不做历史分账流水的回溯重算；
- 不改动 app.py 退款面板的既有布局，只复用后端新的 409 提示。

## 10. 验收口径

1. 门票未核销：不可分账；可退款。
2. 门票已核销、仍有未核销项目、未离园且未闭园：生命周期 `active`，可退款，不可分账，不可离园登记前重复入园。
3. 出口扫码后：
   - 关闭离园后退款：生命周期立即 `completed`，可退款变为 false，可分账变为 true；
   - 开启离园后退款且窗口未到期：`active`，可退款，不可分账；
   - 窗口到期：`completed`，可退款 false，可分账 true。
4. 全部子项已核销或已退款：生命周期立即 `completed`，可立即分账。
5. 闭园时间到达且未扫码离园：按配置执行条件 2 或 3。
6. 生命周期结束后再次核销：409“本次游园已结束，如需再次入园请重新购票”。
7. 未入园调用离园接口：409。
8. 运营配置写入需要签名，非法小时数返回 422。
